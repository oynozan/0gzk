# Reference

The SDK exposes a handful of types and error classes that show up in more than one entry point. This page is the single source of truth. The per-subpath SDK pages link here instead of repeating the shapes.

## Shared types

### `BundleFiles`

```typescript
interface BundleFiles {
  wasm: Uint8Array;
  zkey: Uint8Array;
  vkey: unknown;
  metadata: CircuitMetadata;
  verifier?: string;
}
```

The in-memory representation of a circuit bundle. **`wasm`** and **`zkey`** are raw bytes (handed straight to **snarkjs**), **`vkey`** is the parsed **`verification_key.json`** (kept as **`unknown`** because snarkjs accepts whatever shape it produced), and **`verifier`** is the Solidity source string when **`metadata.files.verifier`** is set and the file exists.

Where it comes from: **`readBundleFromDir`**, **`fetchBundle`**, the callback in **`resolveBundle`**, and the value of **`BuildCircuitBundleResult.metadata`** (after reading).

Used by: **`generateProof`**, **`verifyLocal`**, **`resolveBundle`**.

### `CircuitMetadata`

```typescript
interface CircuitMetadata {
  name: string;
  version: string;
  description?: string;
  tags?: string[];      // free-form discovery tags, e.g. ["identity", "age", "comparison"]
  keywords?: string[];  // extra search keywords not natural in the description ("kyc", "over-18")
  useCases?: string[];  // one-line scenarios: "Gate an 18+ product without collecting DOB"
  protocol: "groth16" | "plonk" | "fflonk";
  curve: "bn128" | "bls12-381";
  inputs: Record<string, InputSpec>;
  outputs: Record<string, OutputSpec>;
  files: {
    wasm: string;
    zkey: string;
    vkey: string;
    verifier?: string;
  };
}
```

The canonical bundle descriptor (typically **`metadata.json`** on disk). **`inputs`** drives **`validateInputs`**, so getting it right is what gives you good error messages before snarkjs runs. **`files`** controls what **`readBundleFromDir`** and **`assembleBundle`** look for inside the bundle directory.

The optional **discovery fields** (**`tags`**, **`keywords`**, **`useCases`**, added in 0.4.0) are ignored by the prover and the validator; they exist for search, catalogs, and registry browsers. All 14 reference circuits in `circuits/` ship with `tags` and `useCases` filled in.

### `InputSpec`

```typescript
type InputVisibility = "public" | "private";

interface InputSpec {
  type: string;
  visibility: InputVisibility;
  description?: string;
  length?: number;
}
```

One entry in **`CircuitMetadata.inputs`**. Recognised **`type`** values:

- **`"uint"`**: non-negative integer scalar.
- **`"bool"`**: boolean scalar (**`true`** / **`false`** / **`0`** / **`1`**).
- **`"field"`**: bn128 scalar field element (decimal/hex string, number, or bigint).
- **`"<T>[]"`**: array of any of the above (e.g. **`"uint[]"`**, **`"field[]"`**).

Unknown scalar types fall through unchanged (forward-compatible). **`length`** is required for fixed-size circom arrays (for example a Merkle **`pathElements[8]`**); when set, **`validateInputs`** enforces the array length exactly.

### `OutputSpec`

```typescript
interface OutputSpec {
  type: string;
  description?: string;
}
```

One entry in **`CircuitMetadata.outputs`**. The SDK does not validate outputs; this exists for documentation, UI rendering (see the browser example), and registry indexers.

### `ProofResult`

```typescript
interface ProofResult {
  proof: Groth16Proof;     // from snarkjs
  publicSignals: string[];
}
```

The return shape of **`generateProof`**, and the argument shape **`verifyLocal`** expects. **`Groth16Proof`** is the snarkjs type (extended by the ambient **`packages/sdk/src/snarkjs.d.ts`** declarations that ship with the SDK).

### `VersionRecord`

```typescript
interface VersionRecord {
  rootHash: string;     // 0x-prefixed 32-byte hash
  vkeyHash: string;     // 0x-prefixed keccak256 of canonical vkey
  verifier: string;     // address(0) when unset
  publisher: string;    // EVM address that called publishVersion
  publishedAt: number;  // Unix timestamp in seconds
  metadataURI: string;
}
```

Decoded form of **`CircuitRegistry.Version`**. Returned by **`getVersion`** and inside the second element of **`getLatest`**'s return. **`publishedAt`** is converted to a **`number`** so it slots straight into **`new Date(record.publishedAt * 1000)`**. **`metadataURI`** doubles as the bundle locator: **`ipfs://`** / **`0g://`** prefixes name the storage backend, anything else means 0G Storage by **`rootHash`** — feed the record to **`parseBundleRef`** (see **[Networks & storage](/networks#bundle-uri-convention)**).

### `CircuitSummary`

```typescript
interface CircuitSummary {
  name: string;
  owner: string;
  versionCount: number;
  latestVersion: string;
}
```

One row returned from **`listCircuits`**. Use it to populate registry browsers and to decide whether to call **`listVersions`** for a given circuit.

### `ResolvedRecord`

```typescript
interface ResolvedRecord extends VersionRecord {
  name: string;
  version: string;
}
```

What **`resolveBundle`** returns as **`record`**. It adds the resolved **`name`** and **`version`** (the version is always concrete, even when the caller only supplied a name; it comes from **`getLatest`** in that case).

### `UploadStage`, `UploadProgress`, `UploadResult`

```typescript
type UploadStage =
  | "packing"
  | "submitting"
  | "streaming"
  | "finalizing"
  | "done";

interface UploadProgress {
  stage: UploadStage;
  message: string;
  rootHash?: string;
  uploadedSegments?: number;
  totalSegments?: number;
  finalized?: boolean;
}

interface UploadResult {
  rootHash: string;              // bytes32 content address to register on-chain
  uri: string;                   // "0g://0x..." | "ipfs://Qm..."
  backend: "0g" | "ipfs";
  txHash?: string;               // 0G-only
  txSeq?: number;                // 0G-only
  finalized?: boolean;           // 0G-only
}
```

**`UploadStage`** walks the **`packing` -> `submitting` -> `streaming` -> `finalizing` -> `done`** path on the 0G backend (**`packing` -> `submitting` -> `done`** on IPFS). **`UploadProgress`** is what arrives in the **`onProgress`** callback you pass to **`uploadBundle`**; **`rootHash`** appears as soon as the Merkle tree is computed (which is before the upload finishes), and **`uploadedSegments`** / **`totalSegments`** appear during **`streaming`**.

**`UploadResult`** is the normalized return value of a successful **`uploadBundle`** call, whichever backend ran. It is what gets serialized into **`.published.json`** by the CLI. **Breaking change in 0.4.0:** **`txHash`** and **`txSeq`** used to be required; they are now optional because IPFS uploads have no storage transaction.

### `BundleFileMap`

```typescript
interface BundleFileMap {
  wasm: string;
  zkey: string;
  vkey: string;
  verifier?: string;
  metadata: string;
}
```

Returned by **`assembleBundle`** (and surfaced inside **`AssembleBundleResult`**). Each value is the **final on-disk path** inside the assembled bundle directory.

### `BuildStage`, `BuildProgress`

```typescript
type BuildStage =
  | "fetching-ptau"
  | "setup"
  | "exporting-vkey"
  | "exporting-verifier"
  | "assembling"
  | "done";

interface BuildProgress {
  stage: BuildStage;
  message: string;
}
```

Emitted by **`buildCircuitBundle`** through its **`onProgress`** callback. Errors thrown inside **`onProgress`** are swallowed by the SDK (same defensive pattern as **`UploadOptions.onProgress`**) so a logger crash never tears down a build.

## Errors

### `InputValidationError`

```typescript
class InputValidationError extends Error {
  readonly issues: string[];
  constructor(issues: string[]);
}
```

Thrown by **`validateInputs`** (and by extension **`generateProof`**, which calls it). The **`message`** field collapses every issue into a bulleted block; **`issues`** keeps each item separately so UIs can render them as a list.

```typescript
try {
  await generateProof(bundle, { birthYear: -1 });
} catch (err) {
  if (err instanceof InputValidationError) {
    for (const issue of err.issues) console.error(issue);
  }
}
```

### `UploadTimeoutError`

```typescript
class UploadTimeoutError extends Error {
  readonly name: "UploadTimeoutError";
  readonly timeoutMs: number;
  readonly rootHash?: string;
  readonly lastProgress?: UploadProgress;
}
```

Thrown by **`uploadBundle`** when the wall-clock budget set by **`UploadOptions.timeoutMs`** expires. Two important caveats:

1. The underlying upload promise is **not cancelled**; finalization continues on the network. Your client just stops waiting.
2. **`rootHash`** is often populated even on timeout (the Merkle tree is computed locally before submission). If you have it, the data is most likely already submitted on chain; you can recover by calling **`0gzk registry register <rootHash> --bundle ./circuit_bundle`** or **`CircuitRegistry.publishVersion`** directly.

### `PtauIntegrityError`

```typescript
class PtauIntegrityError extends Error {
  readonly name: "PtauIntegrityError";
  readonly size: number;
  readonly expected: string;
  readonly actual: string;
  readonly filePath: string;
}
```

Thrown by **`fetchPowersOfTau`** when the BLAKE2b-512 digest of a downloaded or cached Powers of Tau file does not match the entry in **`PTAU_BLAKE2B`**. The mismatch usually means the cached file is corrupt; delete **`filePath`** and rerun.

## Environment variables

The full matrix read by **`loadConfig`** (SDK) and the CLI. Per field the order is **explicit override -> generic `OGZK_*` env -> legacy `OG_*` env -> preset / built-in default**. The `OGZK_*` names are preferred since 0.4.0; every legacy `OG_*` name keeps working.

| Preferred | Legacy | Purpose | Default |
| --- | --- | --- | --- |
| **`OGZK_NETWORK`** | **`OG_NETWORK`** | Registry chain: **`base`**, **`base-sepolia`**, **`0g-mainnet`**, **`0g-testnet`** (aliases **`mainnet`** / **`testnet`**). Unknown values **throw**. | **`base`** (chain ID `8453`) |
| **`OGZK_RPC_URL`** | **`OG_RPC_URL`** | Registry-chain EVM RPC. | preset (`https://mainnet.base.org`) |
| **`OGZK_PRIVATE_KEY`** | **`OG_PRIVATE_KEY`** | Signing key for uploads (0g backend) and registrations. | unset |
| — | **`OG_INDEXER_URL`** | 0G Storage indexer (0g backend only). | preset for `storageNetwork` |
| **`OGZK_STORAGE`** | — | Bundle storage backend: **`0g`** or **`ipfs`**. | **`ipfs`** on Base chains (hence by default), **`0g`** on 0G chains |
| **`OGZK_STORAGE_NETWORK`** | — | 0G chain the 0g backend signs uploads on (**`0g-mainnet`** / **`0g-testnet`**). | selected network if 0G-family, else **`0g-mainnet`** |
| **`OGZK_IPFS_API_URL`** | — | `pinFileToIPFS`-compatible upload endpoint. | `https://api.pinata.cloud/pinning/pinFileToIPFS` |
| **`OGZK_IPFS_API_TOKEN`** | — | Bearer token for the pinning API; required to publish via IPFS. | unset |
| **`OGZK_IPFS_GATEWAY`** | — | HTTP gateway for IPFS fetches (ipfs.io / dweb.link / w3s.link are tried as fallbacks). | `https://gateway.pinata.cloud` |
| **`OGZK_REGISTRY_ADDRESS`** | — | Override the `CircuitRegistry` address (wins over the baked-in map; all four chains have a baked-in entry). | baked-in map |
| **`OGZK_CACHE_DIR`** | — | CLI bundle cache root. | `~/.0gzk/bundles` |
| **`OGZK_CONFIG_DIR`** | — | CLI config directory. | `~/.0gzk` |
| **`OGZK_AGENT_URL`** | — | Hosted [`0gzk agent`](/agent) endpoint the CLI posts to. | `https://0gzk.com/api/agent` |
| **`ANTHROPIC_API_KEY`** | — | Auth for `0gzk agent --local` (falls back to a Claude Code login). | unset |

**Breaking in 0.4.0:** the default network moved from `0g-mainnet` to **`base`**, taking the default storage backend (`ipfs`) and the default `getRegistryContract` chain ID (`8453`) with it. Anything that relied on the implicit 0G default must now set `OGZK_NETWORK=0g-mainnet` (or `--network 0g-mainnet` / `0gzk config set network 0g-mainnet` / `loadConfig({ network: "0g-mainnet" })`).

The **web app** reads the same names, plus `NEXT_PUBLIC_OGZK_NETWORK` (legacy `NEXT_PUBLIC_OG_NETWORK`) as the client-side mirror of the network choice, `NEXT_PUBLIC_OG_EXPLORER` as an explorer override, and `OG_CHAIN_ID` to force the registry-address lookup — see [`web/.env.template`](https://github.com/0gzk/core/blob/main/web/.env.template).

## Repo-level data files

Two machine-readable catalogs ship at the top of the `circuits/` directory in [`0gzk/core`](https://github.com/0gzk/core):

- **`circuits/publications.json`** — committed, per-chain publication records for every reference circuit: chain, chain ID, registry address, version, `rootHash`, `vkeyHash`, publisher, `metadataURI`, storage backend, and transaction details.
- **`circuits/index.json`** — a committed, deterministically generated discovery catalog folding each circuit's `metadata.json` (including the `tags` / `keywords` / `useCases` fields), example input, constraint counts, and publication records. Regenerate with `0gzk catalog build`; CI fails when it is stale.

They power the [MCP server](/mcp) and [`0gzk agent`](/agent).
