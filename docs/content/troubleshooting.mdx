# Troubleshooting

## Next.js / webpack: `Module not found: fs`

**snarkjs** pulls Node builtins. Keep **server-only** imports inside **`import "server-only"`** routes or `next.config` **server externals**, and never import **`@0gzk/sdk/node`** from a Client Component.

If you must bundle snarkjs for the client, add the webpack fallback recommended in [**USAGE.md**](https://github.com/0gzk/core/blob/main/packages/sdk/USAGE.md).

## Browser + 0G indexer CORS

Direct browser fetches against storage indexers may hit **missing CORS** headers. The **[Example 02: Prove in browser](/examples/02-prove-in-browser)** project uses a **dev proxy** so your Vite or Next dev server forwards traffic. In production, proxy fetches through **your** backend.

## CLI exits the process after proving

**snarkjs** can leave worker threads alive. The CLI intentionally calls **`process.exit`** when the command finishes so your terminal is not stuck. This is expected.

## `examples/` folder looks empty

The **`examples/`** directory ships directly in the repo — a plain `git clone` brings it in. If it looks empty, you are likely on a stale checkout; run `git pull`. Then follow any example README.

## `UploadTimeoutError` after `0gzk publish` or `uploadBundle`

0G Storage finalization runs asynchronously and can outlast the default 5-minute budget. When it does, the SDK throws **`UploadTimeoutError`** and the CLI exits with code **`2`** (even after a successful **`--register`**). The error usually carries a **`rootHash`**, meaning the data is already submitted on chain; you just stopped waiting.

Recovery is one command, using the **`rootHash`** the CLI printed:

```bash
0gzk registry register 0x<rootHash> --bundle ./circuit_bundle
```

This recomputes **`(name, version, vkeyHash)`** from the local bundle and calls **`CircuitRegistry.publishVersion`** without re-uploading. From a Node script, do the same thing programmatically:

```typescript
import { UploadTimeoutError } from "@0gzk/sdk/node";

try {
  await uploadBundle(dir, config);
} catch (err) {
  if (err instanceof UploadTimeoutError && err.rootHash) {
    console.warn("upload still finalizing; rootHash:", err.rootHash);
    // Register later, retry the upload, or just exit and let the user recover.
  } else {
    throw err;
  }
}
```

If you want to wait indefinitely instead, pass **`--wait forever`** (CLI) or **`{ timeoutMs: Infinity }`** (SDK).

## IPFS gateway 404 / timeout right after publishing

A freshly pinned CID can take a minute or two to propagate to public gateways like **`https://ipfs.io`** — a 404 or timeout immediately after `0gzk publish --storage ipfs` almost always means **propagation lag, not a lost pin**. Retry after a short wait, or point fetches at your pinning provider's own gateway (which sees the pin immediately):

```bash
# e.g. a Pinata dedicated gateway
0gzk config set ipfsGateway https://your-subdomain.mypinata.cloud
# or one-off:
OGZK_IPFS_GATEWAY=https://your-subdomain.mypinata.cloud 0gzk fetch ipfs://Qm...
```

## Base public RPC rate limits

The default Base endpoints (**`https://mainnet.base.org`**, **`https://sepolia.base.org`**) are public and rate-limited; bursts of registry reads (e.g. paging through `0gzk registry list`) can hit `429`s or hang. Point **`OGZK_RPC_URL`** (or `0gzk config set rpcUrl`) at a dedicated provider endpoint for anything beyond casual use.

## `--legacy` is 0G-only

The `forge` recipes for 0G Chain pass **`--legacy`** because 0G's RPC expects pre-EIP-1559 transactions. **Base uses standard EIP-1559 — do not pass `--legacy` there**; drop the flag from `forge create` / `forge script` invocations when targeting Base or Base Sepolia.

## Registry record vs malicious bundle

Always **verify `vkeyHash`** against **`verification_key.json`** after download. The registry points to content; it does not attest witness correctness for you. Fetch-by-name in the CLI and web app does this check automatically since 0.4.0 and prints a warning on mismatch.
